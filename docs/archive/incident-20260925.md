# Desktop Cursor 切换事故复盘 · 2026-09-25

结论：已有证据支持这条技术通路可行；旧版切换和验收设计不合格。修复版已经通过隔离的
真实 app-server/SDK 工具往返、凭据共存和 daemon 目录缓存实验。用户正在使用的 daemon
没有在本次修复中切换或重启；真实 Desktop GUI 的最终切换验收留到用户在线执行。

## 对事故负责的判断错误

1. **移走 auth.json 是直接破坏。** 旧任务仍固定为 OpenAI，移走凭据后它继续请求 OpenAI
   Responses，却没有 bearer。重连或重启 Desktop 无法补回被移走的登录文件。
   不能为了自定义 provider 的账户界面假设，牺牲已存在的 OpenAI 任务。
2. **把 CLI 的四个 function 当成 Desktop 的全部请求形态。** 事故中第一条新 Cursor
   任务的动态工具有 `codex_app` namespace 和 28 个函数；旧 prepare_request 会立即拒绝。
   当时“namespace 是未来插件问题”的判断错误。第二条失败任务未记录同样的动态定义，
   没有证据把它逐字段归为完全相同的输入。
3. **把重连当成配置激活。** Desktop SSH 使用 proxy 接入远端常驻 daemon；重新连接甚至
   重启 Desktop 都可能继续使用原 daemon。配置恢复正确也不代表 daemon 的目录已更新。
   旧版没有检查真正消费者，却向用户报告切换完成。
4. **验收范围与承诺不相称。** spike 的 24/24 固定样本，以及 CLI/stub 的成功，不能代替
   保留真实账号、插件、namespace 的 app-server 测试，也不能代替切换失败的恢复测试。
   这是实现和验证的缺陷，不是用户没有按要求重启造成的。

用户的外部救援报告 `/tmp/codex-cursor-fallback-incident-20260925.md` 记录了：文件在
23:50:54 恢复，而 23:41:56 启动的 daemon 仍显示三个 Opus。救援重建 daemon 后恢复正常。
本次没有重放报告中的宽泛进程清理操作；临时报告仅作为本机证据，下面保留长期结论。

## 修复后的契约

- v2 切换只管理配置，不移动、删除或覆盖 auth.json，也不修改凭据存储设置。
  旧 v1 只有缺失凭据时才无覆盖发布备份，新登录优先；受管配置冲突拒绝覆盖。
- namespace 函数在 prompt 中使用限定名，输出恢复独立 namespace/name，往返保持 call_id。
  字符串和文本数组工具结果均支持；错误包含受控字段路径，不回显私有输入。
- Cursor 切换先验证运行中的适配服务能力、目录和两输出真实合成工具往返；结果使用只在
  function_call_output 中出现的新随机值，防止模型重复初始指令就通过。失败不动 OpenAI。
- 必须从独立 SSH 终端、Desktop 远程连接已断开且无活跃任务时重启。验证 Unix socket
  peer PID、start_ticks、已知启动参数、工作目录；通过 pidfd 精确停止，不按名称批量杀进程。
  原生 ELF 路径来自已验证的 listener，不盲目启动 PATH wrapper。
- 成功需要新 daemon 的 config/read 和 model/list 匹配。事务记录保留到验收完成；失败
  恢复精确文件版本和原 runtime。外部编辑/陌生进程出现时保留现场，禁止认作本次所有物。
  即使回滚的启动也失败，后续 openai 命令仍能继续恢复，不能形成恢复死锁。
- proxychains 优先解析用户 wrapper 的绝对路径。本机 `/usr/bin/proxychains4` 与用户
  wrapper 使用不同配置，不能依赖 systemd 的默认 PATH 猜测出口。

## 可重复验收与下一次切换

从 skill 根目录运行 SKILL.md 的 unittest 与 `probe_desktop.py --stub`。
`probe_desktop.py --live --effort high|xhigh|max` 显式调用真实 SDK；私有 app-server 使用临时
SQLite/log、ephemeral 任务，保留本机账号和插件形态，不更改 HOME/CODEX_HOME。
探针在任何工具 SSE 发出之前限制为合成工具；模型误选终端/真实插件会立即失败。
`probe_service.py` 检查实际运行的 HTTP 服务，工具结果包含首次指令未知的随机内容。

真实 GUI 验收必须由用户在线完成：独立 SSH 终端进入 skill 根目录 → 等任务结束并断开
Desktop 远程连接 → `scripts/switch.sh cursor --restart-daemon` → 确认退出 0 且
runtime_matches_config=true → Desktop 重连 → 新建 Opus 任务执行一个合成工具往返 →
返回原 OpenAI 任务确认仍可工作。出现失败保留 status 和受控错误，用独立终端执行
`openai --restart-daemon`。原 OpenAI 凭据始终保留，不再要求用户靠外部助手补回登录。
