03

工具调用往返The tool cycle

Select an API format. Then select a step to see the data and SDK state.

选择客户端协议，再逐步查看数据变化和 SDK 状态。下方使用虚构的加法示例，全部交互在浏览器内运行。

SYNTHETIC EXAMPLE · NO API CALLS
POST /v1/responses

  1. The bridge adds each client tool to the SDK tool list. Each tool has a callback.

    桥接器为客户端工具注册 SDK 回调，参数 schema 同时用于校验。

  2. The model starts the callback. The bridge makes a public call ID and a Future to receive the result.

    模型触发回调后，桥接器生成公共调用 ID，并建立等待结果的 Future。

  3. The bridge sends function_call or tool_use to the client. The HTTP response ends.

    桥接器向客户端返回工具调用，结束本次 HTTP 响应；回调仍在等待。

  4. The client operates the tool. Its next request includes the result and the necessary history.

    客户端执行工具。下一次请求携带结果，以及完整历史或可用的 previous_response_id。

  5. The bridge validates each pending call. Correct results complete the waiting Futures. The same SDK run continues.

    桥接器校验整批待处理调用；合法结果完成 Future，使同一 SDK 运行继续。

  6. The SDK run ends. The bridge validates the result and sends the final response.

    SDK 完成后，桥接器检查完整性与模型身份，再发送最终响应。

Each pending call ID must have one result. Missing, duplicate, or changed calls cause a request error.

一次返回必须完整匹配当前待处理批次。缺失、重复或被修改的调用会被拒绝，结果不会被提前消费。

文本实时发送，参数校验后发送Tool arguments wait for checks

The bridge sends text and thinking as it receives them. Tool arguments stream after the callback supplies a full, validated argument object.

文本与 thinking 直接流式转发。工具参数等回调提供完整对象、通过校验后才分块发送，不转发上游未完成的参数片段。

最终响应沿用已经发送的条目 ID 和文本。

终止事件表达真实状态The final event shows the result

A tool response can end while the SDK run waits. A failed stream ends with an error event.

Responses 的 completed 只表示当前响应完成；SDK 可能仍在等工具。流中失败使用错误事件结束。

Messages uses tool_use for tool calls and end_turn for a final answer.

Messages 分别用 tool_use 和 end_turn 表示工具调用与最终回答。

05

状态与恢复State and recovery

A / INFERENCE

推理任务The inference job

The service owns the job. A closed HTTP connection does not cancel active inference.

服务持有推理任务；客户端断开连接不会取消已经运行的推理。

B / WAITING

等待工具结果The waiting callback

A callback waits up to its pending timeout. Its run counts as unfinished work.

回调受 pending_timeout 限制；等待期间仍属于未完成工作。

C / RECOVERY

重试与续接Retries and continuation

An identical request joins its active job or reads a saved response. Failed inference has no automatic retry.

相同请求加入正在运行的任务，或读取已保存的成功结果；失败推理不会自动重试。

State store状态Purpose and limit用途与边界
previous_response_id

The Responses history cache adds earlier history to a later request. It is local memory, with a one-hour lifetime and capacity limits.

本地内存缓存补全历史，保留一小时，最多 32 条且总量不超过 256 MiB；过期或丢失时需发送完整历史。

results.sqlite3

The private ledger saves completed responses for retries. The default retention is one hour, within 256 MiB.

私有账本保存成功响应，默认保留一小时，总量上限 256 MiB。去重摘要包含展开的历史、请求策略和模式。

SDK agent lineage

A validated direct successor can continue the SDK conversation. A branch or changed policy starts a new agent with full history.

经过验证的直接后继可恢复 agent；分支、策略变化或恢复不可用时，用完整历史创建新 agent。

pending callback

User context can follow tool results in the last callback result. Changed history, policy, or other roles need reconstruction.

附加的 user 消息通过专用标记加入最后一个工具结果；历史、策略或其他角色变化会重建运行，并复用已有工具结果。

store: false disables the Responses history cache. The retry ledger and SDK history stay separate. --no-ledger disables ledger retention.

store=false 只关闭 Responses 历史缓存，不会关闭重试账本或 SDK 本地历史；账本保留由 --no-ledger 单独控制。

During reconstruction, matching completed tool calls receive saved results in order. This mechanism does not guarantee exactly-once execution across systems.

重建时，匹配已完成调用的工具按出现顺序取回历史结果。这是基于现有记录的恢复机制，不构成跨系统的 exactly-once 保证。

Other content blocks其他内容块OMITTED

Unsupported Messages content becomes an omission marker. This includes image sources that are not base64.

Why does the bridge use usage estimates?为什么 usage 要使用估算值？

The SDK supplies usage when the run ends. It includes all model calls in that run. Tool responses have no separate SDK usage.

SDK 在运行结束时给出累计用量，覆盖运行内所有模型调用；中间工具响应没有独立的 SDK usage。直接回传累计值会误导客户端的上下文压缩判断。

input_tokens ≈ 3000 + ceil(prompt_bytes / 2.3)
               + 1600 × attached_image_count
output_tokens ≈ ceil(output_bytes / 2.3)
cache counters = 0

These values help clients make an estimate of the context size. They are not exact tokenizer counts or billing records.

估算用于客户端的上下文预算，不是精确分词结果或计费凭据。prompt_bytes 来自桥接器渲染的请求。

07

术语与依据Terms and sources

The English text applies ASD-STE100 writing principles. It uses short sentences, active voice, and the same technical names throughout the text.

Descriptions use at most 25 words per sentence. Instructions use at most 20 words. A specialist must examine full dictionary compliance.

英文按 ASD-STE100 的写作规则组织：短句、主动语态、术语一致；说明句最多 25 词，操作句最多 20 词。完整词典合规性仍需专业审核。中文为辅助对照，不属于英文标准的合规声明。

[D5]

bridge / 桥接器
The local service that changes request and response formats.转换请求和响应格式的本地服务。
client / 客户端
